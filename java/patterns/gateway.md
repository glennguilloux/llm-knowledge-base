# Gateway

> **Autogenerated from:** `references/java-design-patterns/gateway`

## When to Use
- When you need to decouple gateway implementation from client code
- When the gateway logic varies independently from the rest of the system
- When you want to enforce a consistent gateway interface across implementations
- When the gateway behavior needs to be configured or swapped at runtime
- When standardizing gateway handling across a team or codebase

## Common Mistakes

```java
# WRONG: Tight coupling to concrete implementations
# Direct instantiation/usage of specific classes without abstraction layer

# CORRECT: Programming to an interface
# Use an abstraction layer that allows swapping implementations

# WRONG: Violating Single Responsibility
# The gateway pattern handling mixed with unrelated business logic

# CORRECT: Separation of concerns
# Keep gateway logic in dedicated, focused components

# WRONG: Inconsistent error handling
# Different callers handle gateway errors differently

# CORRECT: Centralized error handling
# Use a uniform error handling strategy through the gateway abstraction
```


## Gotchas
- Over-applying gateway when a simpler solution (direct call, if/else) suffices
- Thread safety: gateway implementations often assume single-threaded access
- Testing complexity: mock/stub setup for gateway abstractions can be verbose
