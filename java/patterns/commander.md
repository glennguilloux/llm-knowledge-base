# Commander

> **Autogenerated from:** `references/java-design-patterns/commander`

## When to Use
- When you need to decouple commander implementation from client code
- When the commander logic varies independently from the rest of the system
- When you want to enforce a consistent commander interface across implementations
- When the commander behavior needs to be configured or swapped at runtime
- When standardizing commander handling across a team or codebase

## Common Mistakes

```java
// WRONG: No retry or compensation logic
// When a step fails (payment succeeds but inventory reservation fails),
// there's no rollback — customer is charged but order stays unfulfilled.
public class OrderHandler {
    public void placeOrder(Order order) {
        paymentService.charge(order.total());     // could succeed
        inventoryService.reserve(order.items());   // could fail
        shippingService.schedule(order.address()); // never reached
        // No rollback if any step fails
    }
}

// CORRECT: Use compensating actions or a saga pattern
// Each step has a compensating action for rollback.
public class OrderSaga {
    public void execute(Order order) {
        try {
            paymentService.charge(order.total());
            inventoryService.reserve(order.items());
            shippingService.schedule(order.address());
        } catch (InventoryException e) {
            paymentService.refund(order.total());  // compensate
            throw new OrderFailedException("Inventory unavailable", e);
        }
    }
}
```

```java
// WRONG: Synchronous blocking in command execution
// Waiting for each step to finish before starting the next
// doubles total latency.
public void process(Command cmd) {
    var result1 = step1.execute(cmd);   // 100ms
    var result2 = step2.execute(result1); // 100ms
    var result3 = step3.execute(result2); // 100ms
    // total: 300ms sequentially
}

// CORRECT: Use async command queue with worker pool
// Decouple command receipt from execution for better throughput.
@Component
public class AsyncCommandBus {
    private final ExecutorService workers = Executors.newFixedThreadPool(4);
    private final Queue<Command> queue = new ConcurrentLinkedQueue<>();

    public void submit(Command cmd) {
        queue.offer(cmd);
        workers.submit(this::processNext);
    }

    private void processNext() {
        Command cmd = queue.poll();
        if (cmd != null) {
            cmd.execute();
        }
    }
}
```

## Gotchas
- Distributed transactions across services are expensive. Prefer sagas with compensating actions.
- Ensure idempotency keys on commands so retries don't double-process.
- Commander is overkill for single-process apps — use simple retry + circuit breaker instead.
- Log command execution history for debugging distributed failures.
