# Templateview

> **Autogenerated from:** `references/java-design-patterns/templateview`

## When to Use
- When you need to decouple templateview implementation from client code
- When the templateview logic varies independently from the rest of the system
- When you want to enforce a consistent templateview interface across implementations
- When the templateview behavior needs to be configured or swapped at runtime
- When standardizing templateview handling across a team or codebase

## Common Mistakes

```java
// WRONG: Template View mixing rendering with business logic
// The view template directly queries databases and processes data.
public class DashboardView extends TemplateView {
    @Override
    protected void renderDynamicContent() {
        // Business logic leaking into view
        List<Order> orders = orderRepository.findRecent();
        double total = orders.stream()
            .mapToDouble(Order::getTotal)
            .sum();
        LOGGER.info("Total revenue: " + total);  // formatting in view
    }
}

// CORRECT: View receives pre-computed data, only handles rendering
// Business logic lives in a controller or service layer.
public class DashboardView extends TemplateView {
    private final DashboardData data;

    public DashboardView(DashboardData data) {
        this.data = data;
    }

    @Override
    protected void renderDynamicContent() {
        LOGGER.info("Orders today: {}", data.orderCount());
        LOGGER.info("Revenue: ${}", String.format("%.2f", data.totalRevenue()));
    }
}
```

```java
// WRONG: Putting too much into one template
// A single template view handling all page types
// becomes unmaintainable.
public class MegaView extends TemplateView {
    @Override
    protected void renderHeader() {
        if (pageType.equals("home")) { /* homepage header */ }
        else if (pageType.equals("product")) { /* product header */ }
        else if (pageType.equals("checkout")) { /* checkout header */ }
        // 15 more page types...
    }
}

// CORRECT: One TemplateView per page type
// Each view is focused and testable independently.
public class HomePageView extends TemplateView {
    @Override
    protected void renderDynamicContent() {
        LOGGER.info("Welcome to the Home Page!");
    }
}

public class ProductPageView extends TemplateView {
    @Override
    protected void renderDynamicContent() {
        LOGGER.info("Product: {} - ${}", product.getName(), product.getPrice());
    }
}
```

## Gotchas
- Template View uses inheritance — prefer composition (decorators, helpers) if you need to mix behaviors.
- Keep hooks (overridable methods) to a minimum. Too many hooks make the template hard to reason about.
- Consider using a dedicated templating engine (Thymeleaf, JSP, Freemarker) for HTML output instead of printing from Java.
- Template View tests often require output capture — use System.setOut() or a logging appender.
