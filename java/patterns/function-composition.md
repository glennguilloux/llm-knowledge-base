# Function Composition

> **Autogenerated from:** `references/java-design-patterns/function-composition`

## When to Use
- When you need to decouple function composition implementation from client code
- When the function composition logic varies independently from the rest of the system
- When you want to enforce a consistent function composition interface across implementations
- When the function composition behavior needs to be configured or swapped at runtime
- When standardizing function composition handling across a team or codebase

## Common Mistakes

```java
# WRONG: Tight coupling to concrete implementations
# Direct instantiation/usage of specific classes without abstraction layer

# CORRECT: Programming to an interface
# Use an abstraction layer that allows swapping implementations

# WRONG: Violating Single Responsibility
# The function composition pattern handling mixed with unrelated business logic

# CORRECT: Separation of concerns
# Keep function composition logic in dedicated, focused components

# WRONG: Inconsistent error handling
# Different callers handle function composition errors differently

# CORRECT: Centralized error handling
# Use a uniform error handling strategy through the function composition abstraction
```


## Gotchas
- Over-applying function composition when a simpler solution (direct call, if/else) suffices
- Thread safety: function composition implementations often assume single-threaded access
- Testing complexity: mock/stub setup for function composition abstractions can be verbose
