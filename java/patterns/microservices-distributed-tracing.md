# Microservices Distributed Tracing

> **Autogenerated from:** `references/java-design-patterns/microservices-distributed-tracing`

## When to Use
- When you need to decouple microservices distributed tracing implementation from client code
- When the microservices distributed tracing logic varies independently from the rest of the system
- When you want to enforce a consistent microservices distributed tracing interface across implementations
- When the microservices distributed tracing behavior needs to be configured or swapped at runtime
- When standardizing microservices distributed tracing handling across a team or codebase

## Common Mistakes

```java
# WRONG: Tight coupling to concrete implementations
# Direct instantiation/usage of specific classes without abstraction layer

# CORRECT: Programming to an interface
# Use an abstraction layer that allows swapping implementations

# WRONG: Violating Single Responsibility
# The microservices distributed tracing pattern handling mixed with unrelated business logic

# CORRECT: Separation of concerns
# Keep microservices distributed tracing logic in dedicated, focused components

# WRONG: Inconsistent error handling
# Different callers handle microservices distributed tracing errors differently

# CORRECT: Centralized error handling
# Use a uniform error handling strategy through the microservices distributed tracing abstraction
```


## Gotchas
- Over-applying microservices distributed tracing when a simpler solution (direct call, if/else) suffices
- Thread safety: microservices distributed tracing implementations often assume single-threaded access
- Testing complexity: mock/stub setup for microservices distributed tracing abstractions can be verbose
