# Layered Architecture

> **Autogenerated from:** `references/java-design-patterns/layered-architecture`

## When to Use
- When you need to decouple layered architecture implementation from client code
- When the layered architecture logic varies independently from the rest of the system
- When you want to enforce a consistent layered architecture interface across implementations
- When the layered architecture behavior needs to be configured or swapped at runtime
- When standardizing layered architecture handling across a team or codebase

## Common Mistakes

```java
# WRONG: Tight coupling to concrete implementations
# Direct instantiation/usage of specific classes without abstraction layer

# CORRECT: Programming to an interface
# Use an abstraction layer that allows swapping implementations

# WRONG: Violating Single Responsibility
# The layered architecture pattern handling mixed with unrelated business logic

# CORRECT: Separation of concerns
# Keep layered architecture logic in dedicated, focused components

# WRONG: Inconsistent error handling
# Different callers handle layered architecture errors differently

# CORRECT: Centralized error handling
# Use a uniform error handling strategy through the layered architecture abstraction
```


## Gotchas
- Over-applying layered architecture when a simpler solution (direct call, if/else) suffices
- Thread safety: layered architecture implementations often assume single-threaded access
- Testing complexity: mock/stub setup for layered architecture abstractions can be verbose
