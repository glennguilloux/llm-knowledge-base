# Page Controller

> **Autogenerated from:** `references/java-design-patterns/page-controller`

## When to Use
- When you need to decouple page controller implementation from client code
- When the page controller logic varies independently from the rest of the system
- When you want to enforce a consistent page controller interface across implementations
- When the page controller behavior needs to be configured or swapped at runtime
- When standardizing page controller handling across a team or codebase

## Common Mistakes

```java
# WRONG: Tight coupling to concrete implementations
# Direct instantiation/usage of specific classes without abstraction layer

# CORRECT: Programming to an interface
# Use an abstraction layer that allows swapping implementations

# WRONG: Violating Single Responsibility
# The page controller pattern handling mixed with unrelated business logic

# CORRECT: Separation of concerns
# Keep page controller logic in dedicated, focused components

# WRONG: Inconsistent error handling
# Different callers handle page controller errors differently

# CORRECT: Centralized error handling
# Use a uniform error handling strategy through the page controller abstraction
```


## Gotchas
- Over-applying page controller when a simpler solution (direct call, if/else) suffices
- Thread safety: page controller implementations often assume single-threaded access
- Testing complexity: mock/stub setup for page controller abstractions can be verbose
