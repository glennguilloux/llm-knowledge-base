# Object Mother

> **Autogenerated from:** `references/java-design-patterns/object-mother`

## When to Use
- When you need to decouple object mother implementation from client code
- When the object mother logic varies independently from the rest of the system
- When you want to enforce a consistent object mother interface across implementations
- When the object mother behavior needs to be configured or swapped at runtime
- When standardizing object mother handling across a team or codebase

## Common Mistakes

```java
# WRONG: Tight coupling to concrete implementations
# Direct instantiation/usage of specific classes without abstraction layer

# CORRECT: Programming to an interface
# Use an abstraction layer that allows swapping implementations

# WRONG: Violating Single Responsibility
# The object mother pattern handling mixed with unrelated business logic

# CORRECT: Separation of concerns
# Keep object mother logic in dedicated, focused components

# WRONG: Inconsistent error handling
# Different callers handle object mother errors differently

# CORRECT: Centralized error handling
# Use a uniform error handling strategy through the object mother abstraction
```


## Gotchas
- Over-applying object mother when a simpler solution (direct call, if/else) suffices
- Thread safety: object mother implementations often assume single-threaded access
- Testing complexity: mock/stub setup for object mother abstractions can be verbose
