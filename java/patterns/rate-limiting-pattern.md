# Rate Limiting Pattern

## When to Use
- When you need to decouple rate limiting pattern implementation from client code
- When the rate limiting pattern logic varies independently from the rest of the system
- When you want to enforce a consistent rate limiting pattern interface across implementations
- When the rate limiting pattern behavior needs to be configured or swapped at runtime
- When standardizing rate limiting pattern handling across a team or codebase

## Standard Pattern

```java
package com.iluwatar.rate.limiting.pattern;

/** Exception thrown when AWS-style throttling occurs. */
public class ThrottlingException extends RateLimitException {
  private final String serviceName;
  private final String errorCode;

  public ThrottlingException(String serviceName, String operationName, long retryAfterMillis) {
    super("AWS throttling error for " + serviceName + "/" + operationName, retryAfterMillis);
    this.serviceName = serviceName;
    this.errorCode = "ThrottlingException";
  }

  public String getServiceName() {
    return serviceName;
  }

  public String getErrorCode() {
    return errorCode;
  }
}

```

# WRONG: Violating Single Responsibility

## Gotchas
- Over-applying rate limiting pattern when a simpler solution (direct call, if/else) suffices
- Thread safety: rate limiting pattern implementations often assume single-threaded access
- Testing complexity: mock/stub setup for rate limiting pattern abstractions can be verbose
