# Actor Model

> **Autogenerated from:** `references/java-design-patterns/actor-model`

## When to Use
- When you need to decouple actor model implementation from client code
- When the actor model logic varies independently from the rest of the system
- When you want to enforce a consistent actor model interface across implementations
- When the actor model behavior needs to be configured or swapped at runtime
- When standardizing actor model handling across a team or codebase

## Common Mistakes

```java
# WRONG: Tight coupling to concrete implementations
# Direct instantiation/usage of specific classes without abstraction layer

# CORRECT: Programming to an interface
# Use an abstraction layer that allows swapping implementations

# WRONG: Violating Single Responsibility
# The actor model pattern handling mixed with unrelated business logic

# CORRECT: Separation of concerns
# Keep actor model logic in dedicated, focused components

# WRONG: Inconsistent error handling
# Different callers handle actor model errors differently

# CORRECT: Centralized error handling
# Use a uniform error handling strategy through the actor model abstraction
```


## Gotchas
- Over-applying actor model when a simpler solution (direct call, if/else) suffices
- Thread safety: actor model implementations often assume single-threaded access
- Testing complexity: mock/stub setup for actor model abstractions can be verbose
