## When to Use
- When you need to decouple localization implementation from client code
- When the localization logic varies independently from the rest of the system
- When you want to enforce a consistent localization interface across implementations
- When the localization behavior needs to be configured or swapped at runtime
- When standardizing localization handling across a team or codebase

## Gotchas
- Over-applying localization when a simpler solution (direct call, if/else) suffices
- Thread safety: localization implementations often assume single-threaded access
- Testing complexity: mock/stub setup for localization abstractions can be verbose
