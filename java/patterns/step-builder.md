# Step Builder

> **Autogenerated from:** `references/java-design-patterns/step-builder`

## When to Use
- When you need to decouple step builder implementation from client code
- When the step builder logic varies independently from the rest of the system
- When you want to enforce a consistent step builder interface across implementations
- When the step builder behavior needs to be configured or swapped at runtime
- When standardizing step builder handling across a team or codebase

## Common Mistakes

```java
# WRONG: Telescoping constructors
Many overloaded constructors with different parameter combinations

# CORRECT: Fix
Using a builder with fluent setter methods
```

```java
# WRONG: Mutable builder returned by reference
Returning internal builder state directly

# CORRECT: Fix
Always returning `this` from builder methods and building immutable objects
```

```java
# WRONG: Missing validation in build()
Letting build() return partially initialized objects

# CORRECT: Fix
Validating all required fields in build() before constructing
```


## Gotchas
- Builder pattern adds boilerplate — consider for 4+ parameters, not 2-3
- Consider edge cases specific to your domain before applying
- Profile before and after to validate the pattern benefits
