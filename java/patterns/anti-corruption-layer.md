# Anti Corruption Layer

> **Autogenerated from:** `references/java-design-patterns/anti-corruption-layer`

## When to Use
- When you need to decouple anti corruption layer implementation from client code
- When the anti corruption layer logic varies independently from the rest of the system
- When you want to enforce a consistent anti corruption layer interface across implementations
- When the anti corruption layer behavior needs to be configured or swapped at runtime
- When standardizing anti corruption layer handling across a team or codebase

## Common Mistakes

```java
# WRONG: Tight coupling to concrete implementations
# Direct instantiation/usage of specific classes without abstraction layer

# CORRECT: Programming to an interface
# Use an abstraction layer that allows swapping implementations

# WRONG: Violating Single Responsibility
# The anti corruption layer pattern handling mixed with unrelated business logic

# CORRECT: Separation of concerns
# Keep anti corruption layer logic in dedicated, focused components

# WRONG: Inconsistent error handling
# Different callers handle anti corruption layer errors differently

# CORRECT: Centralized error handling
# Use a uniform error handling strategy through the anti corruption layer abstraction
```


## Gotchas
- Over-applying anti corruption layer when a simpler solution (direct call, if/else) suffices
- Thread safety: anti corruption layer implementations often assume single-threaded access
- Testing complexity: mock/stub setup for anti corruption layer abstractions can be verbose
