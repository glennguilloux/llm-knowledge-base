# Google Wire — Compile-Time Dependency Injection for Go

## When to Use
- Go applications with complex dependency graphs (10+ interconnected services)
- Projects that want DI without runtime reflection (no uber/fx, no dig)
- Reducing manual wiring boilerplate in main.go
- Teams that want explicit, verifiable dependency graphs at compile time

## Standard Pattern

```go
//go:build wireinject
// +build wireinject

package main

import (
	"context"
	"database/sql"
	"fmt"
	"log"
	"os"

	"github.com/google/wire"
)

// --- Step 1: Define providers (plain Go functions) ---

// Provider: creates a database connection
func NewDB(connStr string) (*sql.DB, error) {
	db, err := sql.Open("postgres", connStr)
	if err != nil {
		return nil, fmt.Errorf("open db: %w", err)
	}
	return db, nil
}

// Provider: creates a user repository
type UserRepository struct {
	db *sql.DB
}

func NewUserRepository(db *sql.DB) *UserRepository {
	return &UserRepository{db: db}
}

// Provider: creates a user service
type UserService struct {
	repo *UserRepository
	log  *log.Logger
}

func NewUserService(repo *UserRepository, logger *log.Logger) *UserService {
	return &UserService{repo: repo, log: logger}
}

// Provider: creates a logger
func NewLogger() *log.Logger {
	return log.New(os.Stdout, "[app] ", log.LstdFlags)
}

// Provider: cleanup function example
func NewDBWithCleanup(connStr string) (*sql.DB, func(), error) {
	db, err := sql.Open("postgres", connStr)
	if err != nil {
		return nil, nil, err
	}
	cleanup := func() { db.Close() }
	return db, cleanup, nil
}

// --- Step 2: Define provider sets ---

var DBSet = wire.NewSet(NewDBWithCleanup)
var RepoSet = wire.NewSet(NewUserRepository)
var ServiceSet = wire.NewSet(NewUserService, NewLogger)

var MainSet = wire.NewSet(DBSet, RepoSet, ServiceSet)

// --- Step 3: Define the injector (wire build generates the implementation) ---

// InitializeApp wires everything together at compile time.
// wire.GenerateInjector signals wire to auto-generate the implementation.
func InitializeApp(ctx context.Context, connStr string) (*UserService, func(), error) {
	wire.Build(MainSet)
	return nil, nil, nil // Wire replaces these stubs with real implementations
}

// --- Step 4: Run wire generate ---
// $ cd cmd/app && wire
// This generates wire_gen.go with the actual wiring code

// --- Generated wire_gen.go (auto-generated by wire) ---
// // Code generated by Wire. DO NOT EDIT.
// func InitializeApp(ctx context.Context, connStr string) (*UserService, func(), error) {
// 	logger := NewLogger()
// 	db, cleanup, err := NewDBWithCleanup(connStr)
// 	if err != nil { return nil, nil, err }
// 	userRepository := NewUserRepository(db)
// 	userService := NewUserService(userRepository, logger)
// 	return userService, func() { cleanup() }, nil
// }

// --- Binding interfaces to implementations ---

type Notifier interface {
	Send(ctx context.Context, msg string) error
}

type EmailNotifier struct{}

func NewEmailNotifier() *EmailNotifier { return &EmailNotifier{} }

func (e *EmailNotifier) Send(ctx context.Context, msg string) error {
	fmt.Println("sending email:", msg)
	return nil
}

// Wire binding: interface -> concrete type
var NotifierSet = wire.NewSet(
	NewEmailNotifier,
	wire.Bind(new(Notifier), new(*EmailNotifier)),
)
```

## Common Mistakes

```go
// WRONG: Forgetting to run "wire" after changing providers
// If you add a parameter to NewUserService, wire will NOT auto-update.
// You must run: wire ./... to regenerate wire_gen.go

// WRONG: Using pointer vs value receivers inconsistently
var Set = wire.NewSet(NewService)
// NewService returns *Service (pointer)
// But another provider expects Service (value)
// -> wire will fail with "no provider found for Service"

// CORRECT: Keep provider return types consistent
func NewService() *Service { return &Service{} }  // Always return *Service

// WRONG: Circular provider dependencies
// func NewA(b *B) *A { return &A{b: b} }
// func NewB(a *A) *B { return &B{a: a} }
// wire will detect this at BUILD time and error out

// WRONG: Defining providers for the same type twice
var Set1 = wire.NewSet(NewLogger)  // Provides *log.Logger
var Set2 = wire.NewSet(NewLogger)  // Also provides *log.Logger
// wire.Apply will fail: "multiple providers for *log.Logger"

// CORRECT: Use wire.Value for simple values instead of providers
var ConfigSet = wire.NewSet(
	wire.Value(3000),                     // int (port)
	wire.Value("postgres://localhost:5432"), // string (conn string)
)

// CORRECT: Use wire.Struct to auto-inject struct fields
// Instead of writing providers for every struct field, wire.Struct
// injects all fields marked with `wire:""` tags.
var AppSet = wire.NewSet(
	wire.Struct(new(AppConfig), "*"),  // injects all fields
	wire.Struct(new(HTTPServer), "*"),
)

func InitializeApp(port int, connStr string) (*Server, error) {
	wire.Build(ConfigSet, MainSet)
	return nil, nil
}
```

## Gotchas
- **Provider order doesn't matter:** Wire resolves the dependency graph automatically. You can define providers in any order in the set. Wire builds a dependency graph and finds the correct resolution path at compile time.
- **Cleanup functions compound:** When multiple providers return cleanup functions, they are called in REVERSE dependency order (leaf first, then root). This ensures database connections are closed before services that depend on them stop.
- **Interface binding requires `wire.Bind`:** You cannot just implement an interface and expect Wire to resolve it. You must explicitly bind with `wire.Bind(new(Interface), new(*Impl))` or use `wire.Bind(new(Interface), new(Impl))` for non-pointer types.
- **Wire does NOT support parameter objects:** Unlike uber/fx where you inject a container, Wire only supports individual parameters. A function with 8 parameters means those 8 types must each have a provider. Consider grouping related config into a struct.
- **Build tags are critical:** The `//go:build wireinject` build tag on your injector file means it only compiles when you run `wire`. Without it, normal `go build` would find duplicate `main()` functions. Always add the tag.
